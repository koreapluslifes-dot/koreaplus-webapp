# K-Beauty Library — how it works and what's next

The library at `koreaplus-lifes.com/guide/kb/` is **5,937 English pages** generated by
`build-kbeauty-pages.cjs` from data packs. It grew from 2,254 pages (2026-08) by adding
*data*, never by writing pages by hand.

```bash
node build-kbeauty-pages.cjs && bash deploy-kbeauty.sh --no-build
```

## The one thing to understand

The generator multiplies every dataset. One new ingredient becomes ~10 pages
(guide, ×concern, ×skin-type, mixing pairs, dosage, mechanism, comparisons,
layering, seasonal). One new concern becomes ~30. One new product category
becomes ~30. **So the way to grow this library is to add data, not pages.**

## Adding content

**A new topic cluster** — drop `kbeauty-pack-<name>.json` in the repo root:

```json
{ "<dir>": [ { "slug": "", "title": "", "h1": "", "qa": "", "sections": [ { "h": "", "body": "" } ] } ] }
```

Then add `<dir>` to `PACK_DIRS` (output config) and `HUB_META` (navigation) in the
generator. Nothing else. Unknown keys are reported, not silently dropped.

**New products** — drop `kbeauty-products-<n>.json` with a `products` array. Product
pages, `pick/` comparison pages and brand-page cross-links all generate from it.
Products are deduped by id *and* by brand+name.

**New ingredients / concerns / brands / categories** — extend
`kbeauty-library-ext.json` or `kbeauty-library-ext2.json`. Every ingredient needs a
matching `dose` and `moa` record with the **same evidence grade in both**.

## Why the packs are library-only

The packs are read by the page generator only. `kbeauty-data.js` drives the
interactive hub, whose 14 languages are translated overlay-by-overlay in
`assets/kbeauty-content.<lang>.json`. Adding ingredients there would ship English
into 13 fully-localized hubs. The library is English + hreflang x-default, so it
scales freely. **Do not "fix" this by merging them.**

## Content contract

Non-negotiable, and the reason this library is worth reading:

- Cosmetic structure-function wording — "the look of firmness", never "treats" or "repairs".
- No invented numbers. No statistic you cannot defend.
- Hedge honestly. Thin evidence gets called thin. Popular things get called over-claimed.
- Medical topics defer to a clinician, every time.
- `clinic/`, `condition/`, `rx/` and `pregnancy/` carry standing medical disclaimers
  injected by the generator — do not remove them.

## Build invariants

- **`writeRetry` falls back to temp-file + rename.** Windows denies truncating an open
  file but permits rename, so a plain retry loop can never win against a lock.
- **Orphan pruning.** Any `.html` under `kb/` the build did not write this run is
  deleted. Renamed slugs used to linger and compete with their replacement.
- **`kb-freshness.json`** hashes h1+body only, so meta-description rewrites correctly
  do *not* move `lastmod`. Commit this file — it is what keeps dates honest.
- **Link guards.** Several clusters are conditional (`best/` needs 3+ ranked
  ingredients, `pick/` needs 3+ products, `category/`×concern only covers treatment
  formats). Check `WRITTEN_SET` / `PICK_EXISTS` before linking to them. Every broken
  internal link this library has had came from linking optimistically.

## Verification

A 5-agent adversarial fact-check of the first expansion found 148 issues, 16 high —
a wrong kojic-acid regulatory ceiling, a missing tea-tree leave-on limit, and the
June 2026 FDA approval of bemotrizinol (Tinosorb S) which invalidated four
sunscreen-filter pages. **Regulatory content dates fastest. Re-verify `filter/` and
`functional/` whenever they are touched.**

The QA sweep (broken links, duplicate titles/descriptions, canonical/sitemap
integrity, chrome localization, entity-aware truncation checks) lives in the session
scratchpad — worth promoting into `scripts/` if this library keeps growing.

## Backlog — ranked, from a coverage audit

1. **Product coverage is 140 of a possible many hundred.** The `pick/` machinery is
   built and only needs more `kbeauty-products-*.json` packs. Highest value per unit
   of effort in the whole library.
2. **Adversarial fact-check of round 2** — the 140 products, 54 ingredients and the
   `condition/` `rx/` `fix/` `tone/` `cost/` clusters shipped with an automated risk
   scan only, not the 5-agent verification round 1 received.
3. **`tools/` contains no actual tools.** Four SEO landers with no `<input>`, while
   the library holds 207 INCI entries, 129 dosed actives and a pairing matrix — the
   dataset for a paste-your-label analyzer and a routine conflict checker already
   exists. Tools are the main link-earning asset in this vertical.
4. **The 14-language cluster is still 71 topics** while English is 5,937. The highest-
   value pages (sunscreen filters, conditions, troubleshooting) are English-only.
5. **Wikimedia photography.** Every page is text-only; other verticals in this repo
   pull real images from Wikimedia Commons.
