Every generated SEO page (via `shell()`) has a **top-left home banner**: `<a class="hub-nav-logo" href="index.html" aria-label="KoreaPlus — back to home" title="Home">🇰🇷 KoreaPlus</a>` (base href is `/guide/`, so it goes to the travel home). Plus the `kp-pnav` mega-menu with a **"Browse" dropdown** (the 7 category hubs + All guides), a "Guides" dropdown (festivals/seasons/etc.), and "Where to Go" (top cities + All destinations→destinations.html).

**Drill-down structure (built 2026-06-26):** home → `explore.html` (L1: 8 category TILES, `.seo-tiles` grid in seo.css) → category **hub page** (L2) → individual page (L3). Every page is reachable by clicking through categories. The hubs are generated by **`buildBrowseHubs(out)`** (called right before `buildExplore(out)`) which uses the generic **`buildHub({slug,h1,emoji,lead,badge,sections})`**; result stored in `out.hubs` (used for explore tiles + sitemap). The 7 hubs: `destinations.html` (all 24 cities + food/best-time/stays/neighborhoods/transport = 111 links), `experiences.html` (topics + culture/seasonal + all places), `when-to-visit.html` (seasons+months+best-time), `travel-basics.html` (visa/cost/transport/money FAQ), `itineraries.html`, `tools.html`, `faq/index.html` (FAQ had no index before). To add a hub: add a `reg({...})` block in buildBrowseHubs; it auto-appears as an Explore tile + in the sitemap. Add the root hub filenames to `deploy-seo.sh` ROOTS so they ship (faq/index.html ships via the `faq` dir). seo.css is at **?v=7** (tiles + gradient-emoji hero).

**Localized (2026-06-26):** all 8 locales get their own hub set (64 localized hub pages) via **`buildBrowseHubsL10n(out, lang)`** + a localized `explore.html`, using translated UI from **hub-l10n.json** (`{en, ja, zh, es, ko, fr, de, pt, id}`; en base = hub-l10n.en.json; the 8 langs are produced by the `hub-l10n-translate` workflow — re-run it if you change the en bundle, then deep-merge onto en with en as fallback). Localized hub links resolve to the localized page when it was actually generated (it checks a `built` Set of out.cityL10n/l10n/faqL10n/itinL10n/cost) else fall back to English — so nothing is unreachable; city/FAQ labels use CITY_NAME_L10N / FAQ_L10N. `localizeLinks()` (the shell wrapper for non-en pages) repoints the nav "Browse" hub links + explore.html to `<lang>/…`. Every hub carries a full hreflang cluster via `hubAlts(slug, lang)` (en + 8 locales + x-default). Localized hubs live in the lang dirs (ja/destinations.html …) so they ship via deploy-seo.sh DIRS.
